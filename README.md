# PortLens

Минималистичное приложение на C# с графическим интерфейсом для просмотра локальных портов на Linux и macOS.

## Что умеет

- Показывает слушающие TCP-сокеты и локальные UDP-сокеты.
- Отображает процесс, PID и локальный адрес, когда ОС даёт к ним доступ.
- Ищет по порту, процессу, адресу и PID; фильтрует TCP/UDP.
- Обновляет список по кнопке, не блокируя окно.
- **Живой режим**: обновляет данные каждые 5 секунд, пока включён флажок.
- Подсвечивает новые сокеты зелёным и знаком `+`, считает появившиеся и исчезнувшие записи относительно предыдущего успешного снимка. Первый снимок считается исходным; смена процесса или PID тоже считается изменением.
- Копирует адрес выбранной строки и сохраняет видимый список в CSV.
- Показывает путь, команду запуска, время запуска и память выбранного процесса, если ОС предоставляет доступ.
- Хранит избранные TCP/UDP-порты с подписями между запусками.
- Ведёт историю последних 300 появлений и исчезновений сокетов за время работы окна.
- Проверяет HTTP/HTTPS-сервис по запросу пользователя: код ответа, ошибка или тайм-аут.
- Отправляет SIGTERM своему процессу после подтверждения и повторной проверки его личности.

## Новые возможности

Включи **«Живой режим · 5 сек»**, затем запусти программу, которая использует сеть: её новый сокет подсветится до следующего обновления. Фильтр и выбранная строка сохраняются при обновлении, если сокет остаётся в списке. Счётчик изменений относится ко всему снимку, а не только к результатам поиска. Состояние живого режима и история хранятся только до закрытия окна.

Выбери строку и нажми **«Копировать адрес»** — например, в буфер попадёт `127.0.0.1:8080`. Это адрес привязки, а не ссылка на сайт: `*` означает все интерфейсы.

**«Сохранить CSV»** открывает обычное окно выбора файла. Экспорт учитывает поиск и TCP/UDP-фильтр, содержит время снимка, протокол, адрес, порт, процесс и PID. Список фиксируется в момент нажатия кнопки. В CSV используется UTF-8 с BOM; потенциальные формулы в текстовых полях получают защитный апостроф. Отмена диалога ничего не сохраняет.

Это просмотр локальных сокетов, а не сканирование сети. Привязка к адресу не доказывает доступность порта извне. Некоторые сокеты и процессы скрыты без дополнительных прав; программа не запрашивает sudo. HTTP-запрос отправляется только после нажатия кнопки проверки. Остановка процесса выполняется только после отдельного подтверждения.

## Боковые вкладки

**Процесс.** Выбери строку в списке. Справа появятся подробности, включая путь к исполняемому файлу, команду запуска и память. Команда может содержать личные параметры: сведения показываются локально и не включаются в CSV. Недоступные данные не означают, что процесс отсутствует.

**Проверка веб-сервиса** находится в этой же вкладке. Для TCP-сокета подставляется локальный адрес (для `*` — loopback). Проверь схему `http://` или `https://` и нажми «Проверить HTTP». PortLens отправляет GET и ждёт заголовки до 5 секунд, не следует перенаправлениям, не использует cookies, прокси и автоматическую аутентификацию. Код 404/500 тоже отображается как полученный HTTP-ответ. Произвольный TCP-порт не обязательно обслуживает HTTP; ошибка протокола не доказывает, что сервис неисправен.

**Остановить процесс.** Сначала показывается подтверждение с именем и PID. Остановка мягкая (SIGTERM): процесс может не завершиться или может быть перезапущен системой. Сигнал не отправляется другим пользователям, неизвестному владельцу, PID 1 и самому PortLens. Перед отправкой повторно проверяются владелец и время запуска; принудительного SIGKILL и повышения прав нет. Несохранённые данные выбранной программы могут потеряться.

На Linux остановка требует `pidfd` (ядро 5.3+); на неподдерживаемой системе кнопка недоступна. На macOS между проверкой личности и сигналом остаётся короткое неизбежное окно повторного использования PID. PortLens не предназначен для администрирования от root.

**Избранное.** Введи порт, TCP/UDP и подпись либо возьми выбранную строку. Повторное сохранение той же пары порт/протокол меняет подпись. Статус «Не найден в снимке» не гарантирует, что порт можно занять: у ОС могут быть ограничения видимости. Избранное сохраняется в `~/Library/Application Support/PortLens/favorites.json` на macOS и `$XDG_CONFIG_HOME/portlens/favorites.json` (обычно `~/.config/portlens/favorites.json`) на Linux.

**История.** Хранит до 300 событий в памяти до закрытия окна. Время события — время обнаружения при успешном обновлении, а не точный момент открытия сокета. Короткие события между проверками могут быть пропущены. Ошибка сканирования не создаёт ложное исчезновение всех портов. Кнопка очистки очищает только журнал.

## Запуск

Нужен .NET SDK 10 и графическая сессия Linux или macOS. В репозитории хранятся исходники и тесты; локальные сборки из папки `publish/` в него не входят.

Скачай репозиторий и запусти приложение:

```sh
git clone https://github.com/winnErPy465/portlens.git
cd portlens
dotnet run --project PortLens.csproj
```

Откроется отдельное графическое окно. Также можно открыть папку в VS Code и выбрать задачу **«Запустить PortLens»**. На macOS данные читает системный `lsof`, на Linux — `ss` из пакета `iproute2` (Debian/Ubuntu) или `iproute` (Fedora).

На macOS проверены запуск окна, поиск, чтение реальных сокетов, путь и команда процесса, память, HTTP-ответ тестового сервиса, сохранение избранного после перезапуска, отмена и подтверждение остановки тестового процесса, запись его исчезновения в историю. Сборка Linux x64 создана, но запуск интерфейса и остановка через `pidfd` на настоящем Linux пока не проверялись.

## Сборка для Linux

```sh
dotnet publish PortLens.csproj -c Release -r linux-x64 --self-contained true -o publish/linux-x64
```

Скопируй папку `publish/linux-x64` на Linux и запусти файл `PortLens`. Для ARM64 замени `linux-x64` на `linux-arm64`. Нужна графическая сессия и системные зависимости Avalonia: https://docs.avaloniaui.net/docs/platform-specific-guides/linux .

## Проверки

```sh
dotnet run --project tests/PortLens.Checks.csproj
dotnet run --project tests/features/PortLens.Features.Checks.csproj
dotnet run --project tests/http/PortLens.HttpChecks.csproj
dotnet run --project tests/process/ProcessChecks.csproj
```

Комментарии в коде — на русском.

При проверке на macOS прошли 106 автоматических проверок. Чтение команды запуска через `ps` было недоступно внутри ограниченной тестовой среды, поэтому его дополнительно проверили в обычном окне приложения. Проверка остановки использует только специально созданный тестовый процесс.
